## Local Development

Serve locally with any static file server — no build step required to run the app as-is:

```bash
python -m http.server 8000
# Then open http://localhost:8000
```

The service worker only activates over HTTPS or `localhost`. To test SW updates, use DevTools → Application → Clear Storage between version changes.

### Rebuilding the production CSS

Tailwind is **not** loaded from a CDN (see Architecture below) — `tailwind.css` is a committed, pre-built static file. If you add/remove/change any Tailwind utility class in `index.html` or `script.js`, rebuild it:

```bash
npm install      # one-time, installs the tailwindcss dev dependency
npm run build:css
```

Commit the regenerated `tailwind.css` alongside your change. CI (`.github/workflows/ci.yml`) fails the build if `tailwind.css` is out of date.

### Running tests

```bash
npm test                     # node:test suite for date-utils.js
npm run check:version-sync   # verifies VERSION is in sync (see below)
```

## Architecture

Single-page static PWA — no framework, no bundler required at runtime. A tiny Node/npm dev-only toolchain exists solely to (1) pre-build a purged, static Tailwind CSS file and (2) run tests — nothing is bundled or transpiled, and the app still ships as plain static files.

- `index.html` — UI structure, styled with the pre-built `tailwind.css` (+ `style.css` for custom overrides)
- `date-utils.js` — pure Excel serial ⇄ date conversion functions (no DOM access), loaded before `script.js` and unit-tested via `test/date-utils.test.js`
- `script.js` — UI logic: DOM wiring, i18n, analytics, clipboard, reference tables, the `?format=json` pseudo-API
- `sw.js` — service worker; stale-while-revalidate for same-origin GET requests only (cross-origin/non-GET requests, e.g. analytics, are left untouched)
- `style.css` — minimal custom styles (scrollbar, dark mode fixes only)
- `manifest.json` — PWA installability config
- `assets/flags/*.svg` — self-hosted flag icons (no external flag-icons CDN)
- `tailwind.css` — generated by `npm run build:css` from `tailwind.input.css` + `tailwind.config.js`; commit this file whenever it changes

## Critical: Version Synchronization

**Always increment `VERSION` in `script.js`, `sw.js`, AND the `softwareVersion` field in the JSON-LD block in `index.html` for any change to HTML, CSS, or JS.** Cache invalidation depends on this — users won't see updates otherwise. Run `npm run check:version-sync` (or let CI do it) to verify.

```javascript
// script.js
const VERSION = '1.95';

// sw.js
const VERSION = '1.95';
```

```html
<!-- index.html, inside the JSON-LD <script type="application/ld+json"> block -->
"softwareVersion": "1.95",
```

## Date Calculation

Excel serial dates use `1899-12-30` as Day 0. Always use UTC methods to avoid timezone bugs:

```javascript
const baseDate = Date.UTC(1899, 11, 30);
const serial = (utcDate - baseDate) / MS_PER_DAY;
```

## Internationalization

- Translations live in the `translations` object in `script.js`, keyed by `en`, `da`, `no`, `sv`, `de`
- HTML elements use `data-i18n` attributes; `updateLanguage()` applies translations and re-renders reference tables
- Language auto-detected from `navigator.language`, stored in `localStorage.language`

To add a new language:
1. Add a translation object to `translations` in `script.js`
2. Add the flag SVG to `assets/flags/<xx>.svg` (self-hosted, no external CDN) if not already present
3. Add a button to `#langMenu` in `index.html` with an `<img src="assets/flags/xx.svg">` flag
4. Add detection logic and a `langMap` entry (in `updateLanguage()`) mapping the language to its flag file

## Theme System

- Tailwind `dark:` class-based mode toggled on `<html>`
- System preference detected via `window.matchMedia('(prefers-color-scheme: dark)')`
- User choice persisted in `localStorage.theme`

## Analytics

Google Forms used as analytics backend via `no-cors` POST. Debounced 2 seconds. Entry field IDs in `FORM_ENTRIES` must match the actual Google Form — changing them silently breaks logging.
